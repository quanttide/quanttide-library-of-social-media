# 言序 YanXu（toolsvip.cn）精品调研

> 调研日期：2026-10-30。信息来源：toolsvip.cn 官网前端产物（SPA，含站内指南与公告全文）逐字提取，未采信任何第三方转述。凡站内未公示的（定价、公司主体、开源许可），本文明确标注「未公示」，不做推测。

## 一句话结论

言序是一个**中文排版引擎 + 微信公众号发布通道**：把「排版规范化」和「发布自动化」做成了基础设施——Web 工作台给人用，MCP 端点（`https://toolsvip.cn/mcp`）给 AI 助手用，同一条链路最终都落在「排好版的草稿进公众号草稿箱」。

## 它解决什么问题

站内原话：很多创作者写完文章后还要花大量时间调字体、间距、颜色、结构。「不是大家不想好看，而是从零调字号、间距、颜色、标题样式、列表、图片、文末……太费时间。」所以言序做的事分两层：

1. **规范化**：中英混排的空格与字体、全角半角标点统一、标题与段落的间距与装饰——这是「引擎」的部分；
2. **直出**：排好的富文本经微信公众号 API 推进草稿箱——这是「通道」的部分。

## 核心能力（站内指南可核实）

### 编辑模型

传统编辑器把内容、格式、平台限制混在一起；言序把文章拆成**标题、段落、列表、图片、导语、引用、代码块、文末**等独立模块，每个模块有自己的表达方式。导语有六种形态：简洁导语 / 左侧强调 / 灰底卡片 / 引言式 / 居中导语 / 标签导语。

工作台侧栏：新建文章 / 导入（粘贴纯文本、Markdown、HTML，或上传 .txt / .md / .html / .docx）、「一键排版」、基础设置（默认主题、默认封面、推荐名片）。顶部工具栏：后退、前进、存版本、样式、预览、发布。

### 主题体系

内置六套样式主题，每套都按内容题材写了适用场景：

| 主题 | 适用题材 |
|---|---|
| 霓虹脉冲 | AI、大模型、前沿科技与算力话题 |
| 终端矩阵 | 技术拆解、代码、开发者向内容 |
| 曜金质感 | 高端深度稿、品牌与行业观察 |
| 赤焰警示 | 热点评论、争议快评与燃向话题 |
| 电光靛蓝 | 财报解读、行业数据与深度分析 |
| 紫电深空 | 概念产品、未来科技与发布会内容 |

**百变主题**（v1.03，2026-10-10 上线）：内置约一千套完整风格，打开就能「摇一下」，几秒换一整套；摇到顺眼的可另存成自己的主题复用，喜欢/不喜欢的反馈会留下来帮助筛选。产品判断的依据站内写得很直白：真正从零搭自定义主题的人并不多。

### 版本与发布

- **存版本**：把当前稿固化成快照（备注约 200 字上限），可回滚、可对比；
- **发布**：填标题、选公众号、写摘要、传封面后推送到**公众号草稿箱**。注意——**不是群发**，文章停在草稿状态，仍需到公众号后台手动群发，微信侧做最后确认。

## AI 接入：MCP 是第一公民

言序不只做给人用的界面，它把全部能力暴露成 MCP 端点：

- **端点**：`https://toolsvip.cn/mcp`（streamable HTTP）
- **鉴权**：OAuth。连接器 Headers 必须留空，硬填 token 会和 OAuth 流程打架
- **能力面**：**只有 4 个工具**——查账号、查主题、建稿（拿到 `info_id`）、发布到公众号草稿箱。「这 4 个工具就是言序的全部能力」，链路固定：查账号/查主题 → 建稿 → 发布。
- **已接通的宿主**：豆包工作、千问办公、WorkBuddy（连接器市场搜「言序」）。每个宿主侧分两件东西：**连接器**负责接通（把 MCP 挂进宿主），**技能**负责判断逻辑（先查哪个、字段限制、没封面怎么办、出错怎么恢复）；安装顺序必须先连接器后技能，缺一则链路不通。技能包为 `yanxu-publisher.zip`。
- **硬限制**：自定义连接器仅支持「本地电脑」模式；建稿和发布是**两个动作**，技能文件里明确要求发布前向用户复述文章标题、目标公众号并等待确认。
- **公众号授权**：新版走微信扫码 OAuth 授权，不再需要填 AppID/AppSecret、不再需要配置 IP 白名单；旧版密钥账号迁移截止 2026-10-23，逾期未迁移的公众号旧版推送将失败。

对做 AI 内容工作流的人，这个设计值得注意：**能力面收得极窄（4 个工具）、约束写在技能文件而不是接口层、确认动作留给用户**——这是把 MCP 当发布基础设施而不是聊天玩具的做法。

## 使用时要踩的坑（站内指南明示）

1. **建稿 ≠ 发布**：AI 建稿后文章落在言序，发布是另一次显式动作；
2. **换主题会冲掉微调**：新主题以它的全局样式为基准，之前的细节调整可能丢失；先选主题再微调，或把满意方案存成样式模板；
3. **模板预览不自动保存**：点「存版本」或发布成功后文章才转正；
4. **保存为模板会清空局部样式**：只保留全局样式；
5. **发布异常排查顺序**：版本是否对、公众号是否选错、发布记录里的平台侧状态。

## 与本仓既有材料的关系

`wechat.md` 收录的 md2wechat-skill（github.com/geekjourneyx/md2wechat-skill）解决的是「Markdown → 公众号格式」的**单向转换**；言序在此之上多了三层：排版规范化的引擎层（中英混排、标点统一）、版本与主题的资产层（存版本、千套主题、自建主题复用）、以及公众号 API 的发布层（草稿箱直出 + MCP）。若量潮新媒体矩阵要选公众号排版工具链，言序是目前站内资料可核实、且有 MCP 接口可供 qtmedia / media-toolkit 对接的候选。
